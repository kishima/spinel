# Process-wide data the SP_MULTI_CTX archive may keep (test/multi_ctx/check_globals.sh).
#
# Every other data/bss symbol in lib/libspinel_rt_mc.a is a leak: state one
# instance would share with another. Upstream adds runtime state all the time
# (109 such symbols at the fork point, 377 at 01521b1e), and a new one does
# not show up as a merge conflict -- only here.
#
# Format: <object> <symbol|glob> <class>  # reason
# A trailing .N on a function-local static (buf.0) is the compiler's; the gate
# strips it, so list the bare name. Classes:
#   RO      read-only after the first touch: const tables, init-once caches
#           whose every writer stores the same values
#   CONFIG  set once from the environment by a process constructor, before any
#           instance exists; read-only after
#   SAME    every instance stores the same value (a hook pointing at the same
#           runtime function)
#   DIAG    diagnostics only (SPINEL_GC_PHASES / SPINEL_GC_STATS output); racy
#           counts under concurrent instances, never read for a decision
#   THREADS state of the SP_THREADS parallel collector / scheduler; stays at its
#           initial value in a single-threaded instance
#   NOSLAB  the slab allocator, compiled out under SP_MULTI_CTX (SP_NO_SLAB):
#           never written
#   PORTOUT a module a port leaves out of its build (fibers, the green-thread
#           scheduler, sockets, crypt(3)); unsupported in an instance
#   PROCESS genuinely process-wide: the thread-local current-instance pointer,
#           the standard streams, ARGF's line buffer
#   SCRATCH a shared scratch buffer on an error or rarely-used path; two
#           instances hitting it at once would garble a message, not the heap
